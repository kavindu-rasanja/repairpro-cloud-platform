# Contributing

This repository is currently a private, documentation-first commercial project.

## Guidelines

- Keep statements factual and distinguish implemented behavior from proposals.
- Update related architecture and release documents when a decision changes.
- Never include credentials, production logs or customer-identifiable data.
- Use an Architecture Decision Record for material architecture changes.
- Use clear headings, concise language and Mermaid diagrams where useful.
- Include test evidence when documenting implemented behavior.

## Suggested branch and commit conventions

- Branches: `docs/<topic>`, `feat/<topic>`, `fix/<topic>`, `security/<topic>`.
- Commits: `docs: ...`, `feat: ...`, `fix: ...`, `security: ...`.

## Review

Before merging, check links, spelling, diagrams, secret exposure and consistency with the current product release.
