# Incident Response Runbook

1. **Detect:** identify the alert, reporter and affected service / version.
2. **Triage:** determine impact, scope, severity and whether personal or financial data is involved.
3. **Contain:** disable affected credentials, isolate vulnerable components or pause risky processing.
4. **Preserve:** retain relevant logs and timestamps with access controls; do not expose personal data.
5. **Recover:** deploy a tested fix or restore service using the approved recovery procedure.
6. **Verify:** confirm tenant isolation, data integrity, sync health and customer workflows.
7. **Communicate:** notify affected stakeholders according to the approved incident and legal process.
8. **Review:** record root cause, timeline, corrective actions and owners.
